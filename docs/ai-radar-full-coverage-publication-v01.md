# Wave 5 全覆盖评级与最终草稿发布 v0.1

## 目标

本流程把 Wave 5 的 8,183 条结论统一为可公开展示的 AI 轨道：

- 265 条逐条研究后的固定等级；
- 7,918 条基于已有可追溯摘要生成的有界范围；
- 0 条“已扫描但没有有效结论”。

同时重新读取数据库中所有最新草稿，把任何已有固定 AI 等级或有效范围纳入最终发布筛选。

## 范围评级语义

有界范围保留：

```text
bestGrade
likelyGrade
worstGrade
confidencePercent
evidenceCoveragePercent
uncertaintyReasons
```

现有 Works 的兼容 AI 等级使用 `likelyGrade`，但 `RadarResearchRecords` 保存完整范围。公开详情页已能并列展示：

```text
AI / 规则建议等级：最可能等级
AI 研究档案：最好 ～ 最坏
人工参考轨道：独立保存
```

范围结果始终标记为待人工复核，不能冒充人工确认或逐部精确考据。

## 结论优先级

```text
Wave 5 新精确结果
> 数据库最新草稿固定等级
> 数据库最新草稿有效范围
> 已发布固定等级
> 已发布有效范围
> Wave 5 新粗评范围
```

因此新粗评不会覆盖旧的精确 v0.6 结论。

## 最终发布筛选

只有以下记录会阻断：

- Works 对象缺失；
- `workId` 与 `siteId` 指向不同对象；
- `catalogStatus=archived`；
- `reviewStatus=deprecated`；
- 没有有效固定等级或有效范围；
- 执行时数据库状态已在计划之后发生变化；
- 找不到完成安全 roundtrip 所需的版本。

人工轨道不会阻断 AI 轨道发布。存在人工结论时，仅发布：

```text
_status
radarAssessment
```

不会修改 `humanAssessment`、旧人工记录或目录兼容等级。

## 为什么不能直接发布整份草稿

Payload 的普通 `_status=published` 更新会把最新草稿中的其他字段一起提升到公开主记录。仓库已经永久禁用了旧的一行发布器。

本流程先比较公开主记录与最新草稿：

1. 除 Radar 字段外完全一致时，执行字段级直接发布；
2. 存在无关草稿差异时：
   - 恢复与当前公开主记录完全匹配的历史版本；
   - 发布允许的 Radar 字段；
   - 恢复原最新草稿；
   - 验证公开 Radar 已保留、人工字段未变、原草稿完整恢复。

## 研究记录

每个 Wave 5 结论都会幂等写入一条：

```text
researchKey =
wave5-full-coverage-v01|workId|siteId
```

固定等级在研究轨道中表现为相同的 best/likely/worst；范围评级保留真实边界。

## 两阶段执行

### 阶段一：预检

在 Draft PR 分支执行：

- 校验固定 ZIP 和全部内部哈希；
- 安装 8,183 条结论；
- 运行静态测试；
- 只读读取 Payload 的公开 Works、最新草稿和研究记录；
- 生成完整发布计划；
- 不执行数据库写入；
- 生成预检检查点。

### 阶段二：正式执行

仅在 PR 合并后的 `main`：

- 创建新鲜的 `pg_dump` 自包含备份；
- 验证当前 Git 提交与备份证明；
- 幂等创建/更新研究记录；
- 按字段级直接发布或版本 roundtrip 发布；
- 每条写入可恢复 ledger；
- 最终重新读取全库并统计公开 AI 结论覆盖。

## 安全约束

- 不直接写 PostgreSQL 数据；
- 不发布整份历史草稿；
- 不修改人工轨道；
- 不复活归档或废弃作品；
- 不让粗评范围覆盖精确等级；
- 执行中一旦在写入后出现不可验证异常，立即停止；
- 支持根据 ledger 恢复执行。
