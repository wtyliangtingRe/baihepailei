# Radar 作品级多语言研究与深挖规则 v0.1

状态：长期规则已锁定；适用于所有 canonical Work 的 AI 研究、复核、补来源和后续 supersession。

## 1. 每部作品都必须被搜索

每个 canonical Work 至少完成一次标准化外部研究扫描。冷门、资料稀少或没有社区讨论，不得成为“没有搜索”的理由。

标准扫描至少覆盖：

- canonical identity、原名、中文名、英文名、罗马字和已知别名；
- 官方作品页、角色页、路线或章节说明、出版社或开发商资料；
- Bangumi、AniList、VNDB 等结构化数据库及其外部链接；
- 攻略、全结局、路线表、奖杯或成就说明；
- Wiki、逐章或逐话摘要、改编差异资料；
- 长评、通关报告、完结讨论和社区排雷讨论；
- 中文、日文、英文三种语言的定向搜索。

搜索过但没有找到资料，必须记录为 `searched_no_public_discussion_found`；不得与“尚未搜索”混为一类。

## 2. 标准扫描与深挖分层

所有作品都执行标准扫描，但不要求对每部作品无限重复相同搜索。

以下作品必须进入作品级深挖：

- 拟评 S 或 A，需要主动排除隐藏雷点；
- 拟评 E 或 F，需要为严重负面判断提供更强证据；
- 游戏、视觉小说、多路线或多结局作品；
- 出现男性恋爱、亲密、前任、替身、NTR、姬恋直或路线污染信号；
- 官方资料、攻略、评论之间存在冲突；
- 动画、漫画、小说、游戏等版本可能存在改编差异；
- 仍在连载或结局状态可能变化；
- 仅有一个独立来源；
- 标题、译名、版本或 canonical identity 不稳定。

结构清楚、多个独立来源一致且不存在高影响风险的作品，在标准扫描达到验收条件后可以结束本轮研究。

## 3. 搜索语言与查询结构

每部作品使用原名、中文名、英文名、罗马字、别名、系列名和重要角色名组合查询。

常用中文意图：

- 攻略、路线、全结局、真结局、最终话、最后和谁在一起；
- 百合、恋爱、男性路线、男朋友、前男友、NTR、排雷、剧透。

常用日文意图：

- `攻略`、`全ルート`、`エンディング`、`真エンド`、`最終回`、`結末`；
- `百合`、`恋愛`、`男性ルート`、`元彼`、`寝取られ`、`ネタバレ`、`感想`。

常用英文意图：

- `walkthrough`、`route guide`、`all endings`、`true ending`；
- `yuri review`、`male route`、`ending explained`、`spoiler review`、角色关系查询。

允许使用站点限制定位 Steam Community、VNDB、Bangumi、Reddit、Wiki 或日文攻略站，但站点名本身不等于证据质量。

## 4. 来源类型与证据权重

来源按其能证明的具体事实使用，而不是按网站名机械打分。

大致优先级：

1. 作品正文、实际路线、章节、结局或直接剧情记录；
2. 官方角色关系、路线说明、结局说明、作者或制作人员访谈；
3. 完整攻略、逐章 Wiki、全结局或成就资料；
4. 能指出具体章节、路线和事件的长评或通关报告；
5. 短评、标签、投票、搜索摘要，只作为线索。

官方宣传可能主动回避剧透，因此在路线和最终结局问题上，完整攻略或实际通关记录可以比宣传简介更有决定力。

## 5. 社区材料的使用方式

论坛、贴吧、Reddit、Steam 评论和其他社区内容不得整段直接转成批量自动结论。

必须先把评论拆成可验证的事实主张，例如：

- 某章是否发生告白、接吻、交往、分手或男性亲密；
- 某路线是否可选、强制或属于真结局前置；
- 最终关系是否明确、开放、降格或转向男性；
- 评论对应哪一种媒介、平台、版本和时间点。

严重雷点通常需要直接或官方证据，或者至少两份相互独立且具体情节一致的二手来源。只有一条模糊短评时，只能记录为风险线索和不确定性，不能冒充已证实事实。

## 6. 独立来源判断

不同 URL 不一定代表不同独立来源。

以下情况不能机械计成多个独立提供方：

- 同一数据库的网页、API 和镜像；
- 聚合站复制官方简介；
- Wiki、论坛和视频都引用同一原始帖子；
- 同一作者在多个平台重复发布同一内容。

研究账本必须记录 traceable URL、provider host、来源类别和可能的上游依赖。`sourceCount` 应反映可追溯证据数量，独立提供方数量另行记录。

## 7. 支持证据、反证与冲突

研究不能只寻找支持初始猜测的材料。

每次深挖同时执行：

```text
支持证据搜索
+ 反证搜索
+ 冲突搜索
```

拟评 S/A 时主动寻找前任、男性路线、强制男性事件、结尾降格和版本反转；拟评 E/F 时主动确认严重指控是否只是坏结局、误读、玩梗或版本差异。

冲突材料不得被静默丢弃。需要记录说法、版本、时间点、直接性、独立性和最终采用理由，并通过 `contradictions`、置信度、覆盖度和 `requiresHumanReview` 表达不确定性。

## 8. 冷门作品与搜不到资料

搜不到不等于不存在风险，也不等于允许 AI 轨道为空。

完成标准扫描后仍无公开讨论时，AI 结论必须：

- 保留当前最合理的 grade 和 decisive rule；
- 使用真实且较低的 `sourceCount`；
- 降低 confidence 和 evidence coverage；
- 标记 `requiresHumanReview = true`；
- 在 sourceSummary 中明确已搜索语言、来源类别和未找到的关键信息。

后续发现新资料时，由新 AI snapshot supersede 当前结论；不得回写或覆盖 human track。

## 9. 研究账本

每个 canonical Work 至少保留一份内部研究账本，能够回答“搜了什么、找到什么、没找到什么、为什么这样评”。建议字段包括：

```json
{
  "workId": "canonical-id",
  "identityConfirmed": true,
  "languagesSearched": ["zh", "ja", "en"],
  "sourceClassesAttempted": [
    "official",
    "structured_database",
    "walkthrough",
    "wiki",
    "long_review",
    "community_discussion"
  ],
  "queriesUsed": [],
  "traceableUrls": [],
  "independentProviders": 0,
  "directPlotEvidenceFound": false,
  "counterEvidenceSearched": true,
  "conflictsFound": 0,
  "standardScanStatus": "complete",
  "deepDiveStatus": "not_required_or_complete",
  "searchedAt": "ISO-8601"
}
```

查询中可能包含剧透或不稳定页面，公共页面不必展示全部查询；但内部审计必须能够验证搜索确实发生。

## 10. 完成与质量门槛

一条 AI 研究只有在以下条件满足时才能标记为标准扫描完成：

- canonical identity 和媒介版本已确认，或明确记录 identity blocker；
- 中文、日文、英文均已尝试；
- 六类来源均已尝试，无法适用的类别有原因；
- 支持证据与反证均被搜索；
- 结局、路线、男性介入和关系状态等决定性问题已有结论或明确未知；
- 严重雷点没有仅凭一条模糊社区短评定案；
- 研究账本、来源、冲突和不确定性可以追溯；
- 没有资料时仍生成显式低置信度 AI 结论，而不是伪造安全或留下空轨道。
